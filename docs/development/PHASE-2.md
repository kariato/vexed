## Reproduce

From a clean checkout with the supported Node 22.12+/24 runtime and locked dependencies:

```sh
npm ci
npm run packs:convert
npm run packs:audit
npm run packs:check
npm run check
```

- `packs:convert` produces the normalized reference catalogue, Classic runtime JSON, manifest and conversion report.
- `packs:audit` executes all original solutions through the TypeScript engine and emits the replay report.
- `packs:check` compares all generated bytes and replay results without rewriting them. Stale artifacts, missing/changed source files or unexplained failures cause a nonzero exit.
- `npm run check` includes conversion/replay verification in addition to lint, strict typechecks, tests and build. CI runs it on Node 22 and 24.
- Optionally compare the original local extraction with `npm run packs:convert -- --check --source-dir=.reference/source/vexed/levelpacks`.

No downloaded archive, Palm executable, compiler, .reference cache or network connection is needed to run the committed fixture checks after installing npm dependencies. The optional original-C trace recapture uses the ignored Phase 0 source cache and `cc`.

## Import contract

The INI parser preserves repeated Level sections and reports file/line context. It splits the first equals sign, preserves punctuation in values, rejects duplicate properties and unknown sections, and does not invent escaping rules.

The PDB parser reads big-endian DATA/Vexd record databases with bounded section offsets and NUL-terminated strings. It rejects truncated headers/tables, invalid offsets, chained lists, wrong database kinds, invalid section bounds and unterminated strings. Archive text is decoded as Latin-1 to preserve its byte mapping.

Board decoding validates exactly eight ten-cell rows. Decimal wall runs, tilde air and a–h blocks follow the original format. Unknown symbols and oversized runs fail before allocation. Solutions use the audited coordinate-pair codec; missing data is represented explicitly rather than fabricated.

Every committed source byte is checked against the Phase 0 archive manifest before parsing. Level counts are cross-checked against the native audit. IDs derive from filenames, with stable classic/classic-ii aliases. PDB is the canonical catalogue format; overlapping INI files are compared field by field, not silently dropped.

## Two legacy discrepancies

### Classic II index 3: alternative reference solutions

The INI has par 64 and the PDB has par 36 for the same board/title. Both solutions solve. The exact source and solution hashes are pinned in source-variants.json. The canonical PDB catalogue retains par 36; the INI remains preserved and replayed at par 64. Other metadata/board differences still fail conversion, and stale/unused exceptions fail checks.

### Classic II index 20: one empty-origin encoded step

Pair Hg at zero-based step 36 points at air at (7,6). The original C engine leaves the board unchanged but counts one step. This appeared twice in the source audit because the INI and PDB contain the same solution.

The captured original-C trace confirms every intermediate board, count and final win. The normal player reducer still rejects an empty origin. An explicit one-step `applyReferenceMove` adapter shares the same reducer/settling implementation and is used by the audit only when source hash, level ID, step, coordinates, direction and prior-board hash exactly match the registered exception.

Both occurrences are reported as legacy empty moves, not hidden as successful ordinary player actions. Unknown corrupt reference moves continue to fail. Reproduce the C trace with:

```sh
python3 scripts/capture_empty_move_reference.py --check
```

## Runtime loading and validation

`src/data` defines a versioned pack/manifest boundary and validates IDs, level indices, par, board geometry, symbols and provenance. Fetch helpers use the configured Vite base path, including /vexed/. They reject request/response identity mismatches and HTTP failures. JSON objects are copied to avoid aliasing untrusted parsed data.

The manifest hash supports reproducible builds and later cache policy. The current fetch helper validates schema/identity; it does not independently verify the response body against the manifest hash. Caching, update integrity and persistence remain Phase 5 work.

The browser screen remains the authored Phase 1 engine demonstration. Phase 3 will wire in the Classic pack and provide full touch/keyboard controls; no public deployment or physical-tablet verification is included here.
